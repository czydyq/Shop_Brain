## 完整版

**项目名称**：掌柜智库 —— 电商商品知识库智能问答系统
**时间 / 角色**：2026.03 – 2026.04 ｜ 独立设计与开发（约 8,000 行 Python，83 个模块）
**技术栈**：Python、LangGraph、FastAPI、Milvus、BGE-M3、bge-reranker-large、MinerU、Qwen 系列 LLM、MinIO、MongoDB、SSE、MCP、Pytorch

**项目简介**：
面向电商店铺的 RAG 智能问答系统。店铺销售的商品（万用表、网关、交换机等）附带的 PDF 说明书被批量导入知识库，顾客/客服提问时，系统检索说明书内容并流式生成可靠回答，降低人工客服成本、抑制大模型幻觉。独立完成从文档解析、切分、嵌入、入库到多路召回、重排、生成的全链路设计与开发。

**核心工作**：

1. **双 Pipeline 架构设计**：基于 LangGraph StateGraph 分别编排「文档导入链」（入口路由 → PDF 解析 → 图片处理 → 结构化切分 → 商品名识别 → 向量化 → 入库，含条件路由）与「查询链」（商品名对齐 → 三路并行召回 → RRF 融合 → 精排 → 流式生成，fan-out/fan-in 并行汇聚）；抽象 BaseNode 基类统一节点日志、耗时统计与异常封装。

2. **多模态文档解析与层级感知切分**：采用 MinerU 将 PDF 说明书解析为 Markdown；扫描定位图片引用并抽取上下文，调用视觉大模型（Qwen-VL）生成图片中文摘要，上传 MinIO 后回写正文，使图片内容可被文本检索；自研表格线性化工具处理合并单元格、KV 表、交叉表等四种表格形态。切分层基于标题层级追踪（hierarchy 数组）+ 递归字符切分器二次切分 + 同父短块合并，chunk 携带 title / parent_title / file_title 三级元数据，保障检索上下文完整。

3. **商品名对齐机制（核心创新）**：导入时由 LLM 抽取「品牌+型号+品类」完整商品名并构建独立向量集合；查询时先结合 MongoDB 多轮对话历史做意图识别与指代消解改写，再将用户提到的商品名与集合对齐（确认 / 候选确认 / 未知三分支），对齐结果作为 Milvus expr 过滤条件下沉到检索层，从源头压缩检索噪音、减少幻觉。

4. **三路并行召回 + 两级排序**：召回层采用 BGE-M3 稠密（1024 维 COSINE）+ 稀疏双向量混合检索（WeightedRanker）、HyDE 假设文档检索（LLM 生成 200–300 字假设性文档后编码检索，弥合查询-文档语义鸿沟）、MCP 协议对接联网搜索，三路并行；融合层对本地两路结果做 RRF（k=60，chunk_id 去重）；精排层用 bge-reranker-large 本地 GPU 推理（fp16），分数 sigmoid 归一化后按「断崖式分差 ≥0.15」动态截断 top_k（3–10 条），兼顾上下文长度与答案质量。

5. **数据驱动的阈值调优**：针对商品名对齐的 confirm / options / gap 三阈值，搭建四步调优流水线——构建四类标注用例 → 连接真实 Milvus + BGE-M3 采集检索分数 → 网格搜索 170+ 组合 → 注入配置端到端验证，最终对齐准确率 **93.75%**，结论固化进生产配置。

6. **工程化落地**：FastAPI 双服务（导入 8000 / 查询 8001），BackgroundTasks 异步导入 + 前端轮询节点级进度；查询侧 SSE 流式输出（progress / delta / final 三类事件）实现打字机效果；MongoDB 存储多轮会话支持上下文改写；AIClients / StorageClients 双检锁线程安全单例管理模型与存储连接；定义节点级异常体系（PdfConversionError / EmbeddingError / MilvusError 等）与维度校验、auto_id 重试等防御性处理。

**项目成果**：独立完成全链路开发；商品名对齐准确率 93.75%；系统支持多手册同名商品、模糊指代、无关问题等多种边界场景的自然处理。

## 面试可能的追问点（备用）

- 为什么用稀疏+稠密双向量？→ BGE-M3 一个模型同时产出两种表征，稠密管语义、稀疏管关键词（型号如 "RS-12" 这类精确 token），WeightedRanker 0.5/0.5 融合。
- HyDE 的原理与成本？→ LLM 先生成假设性答案文档再拿去检索，缓解 query 与文档的表述不对称；会多一次 LLM 调用，故与另两路并行执行摊平延迟。
- 断崖式 top_k 截断怎么设计？→ 精排分数 sigmoid 归一化后，寻找相邻名次分差 ≥0.15 的最大断崖处截断，下限 3 上限 10，避免低相关 chunk 污染上下文。
- 阈值为什么靠网格搜索而不是拍脑袋？→ 三阈值（confirm/options/gap）耦合，单纯看单指标会顾此失彼；基于真实采集分数离线穷举，再端到端验证防过拟合。
- 表格为什么要线性化？→ Markdown 表格直接嵌入向量会丢结构；针对 rowspan/colspan、KV 表、交叉表分别展开为自然语言。
